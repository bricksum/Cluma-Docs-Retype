# 컨테이너 관리

Cluma에서 GPU 개발 환경(컨테이너)을 생성하고 접속하는 방법을 안내합니다.

---

## 컨테이너 목록

사이드바에서 **컨테이너**를 선택하면 그룹에 속한 컨테이너 목록이 표시됩니다.

| 열 | 설명 |
|------|------|
| 이름 | 컨테이너 이름 (클릭 시 상세 페이지) |
| 상태 | 현재 실행 상태 |
| 사용자 | 생성한 사용자 |
| 그룹 | 소속 그룹 |
| 작업 | 빠른 접속 (VS Code · SSH · Jupyter) / 삭제 |

**상태 / 사용자 / 그룹** 열은 클릭 시 필터 드롭다운이 표시됩니다. **이름** 열은 오름차순/내림차순 정렬이 가능합니다.

### 상태 색상

| 상태 | 색상 | 의미 |
|------|------|------|
| Creating | 파랑 | 생성 중 |
| Pending | 연한 파랑 | 스케줄링 대기 |
| Running | 초록 | 정상 실행 |
| Deleting | 노랑 | 종료 중 |
| Stopped | 회색 | 종료됨 |
| Failed | 빨강 | 오류 (CrashLoopBackOff, ImagePullBackOff 등) |
| Completed | 남보라 | 정상 종료 |

---

## 컨테이너 생성

**새 컨테이너 만들기** 버튼을 누르고 컨테이너를 배치할 노드를 선택하면 **컨테이너 시작** 모달이 열립니다. 모달은 두 가지 진입점을 제공합니다.

### 1) 템플릿으로 시작 (원클릭)

모달 상단에 그룹 내 저장된 템플릿 카드가 표시됩니다. 카드에는 템플릿 이름 · 이미지 · 인스턴스 종류(예: `A100 × 1`) · Shared Memory · 마운트 개수가 표시됩니다.

1. 원하는 템플릿 카드를 선택합니다.
2. 확인 모달에서 컨테이너 이름을 입력합니다.
3. **생성**을 클릭하면 즉시 만들어집니다.

!!!note 템플릿 삭제
템플릿 카드에 마우스를 올리면 휴지통 아이콘이 표시됩니다. 클릭 시 삭제 확인 모달이 열립니다. (편집은 미지원 — 같은 설정으로 새로 만들어 저장)
!!!

!!!warning 템플릿 사용 불가
템플릿에 기록된 스토리지 중 하나라도 삭제됐으면 컨테이너를 만들 수 없습니다. "스토리지 누락" 배지가 카드에 표시되고, 누락된 스토리지 이름이 안내됩니다.
!!!

### 2) 새로 시작 (인스턴스 직접 선택)

모달의 **또는 새로 시작** 영역에서 인스턴스 카드를 선택해 2단계 마법사로 진행합니다.

#### Step 1 — 인스턴스 선택

노드의 가용 자원을 기반으로 자동 산정된 인스턴스 카탈로그에서 선택합니다.

- GPU 수 × 노드 비례 CPU / 메모리
- 가속기 비탑재 노드는 CPU 전용 인스턴스만 표시
- 가속기 탑재 노드에 CPU 전용 인스턴스는 표시되지 않습니다 (GPU 1개 이상 필수)

**다음** 클릭 시 자원이 **5분간 임시 예약**됩니다. 그 안에 Step 2를 마쳐야 합니다.

#### Step 2 — 컨테이너 옵션

| 항목 | 설명 |
|------|------|
| 컨테이너 이름 | 식별 이름 |
| 이미지 | 직접 입력 / 레지스트리 탐색 / 커스텀 이미지 (3가지 라디오) |
| Shared Memory | `/dev/shm` 크기 (GB). 멀티 GPU 학습 시 필요 |
| 환경 변수 | 이름 · 값 쌍, 여러 개 추가 가능 |
| 실행 명령어 | 이미지 Entrypoint를 덮어쓸 때 사용 (선택) |
| 스토리지 마운트 | 기존 스토리지를 컨테이너 경로에 마운트 (다중 가능) |
| SSH Key | 프로필에 등록한 Key 선택 시 컨테이너에 자동 주입 |
| NUMA-aware CPU 할당 | 동일 NUMA 노드 내에서만 CPU 코어 선택 (선택) |
| 템플릿으로 저장 | 위 설정을 그룹 내 공유 템플릿으로 저장 (선택) |

**NUMA-aware CPU 할당**: 토글 활성화 시 메모리 접근 지연을 줄여 고성능 워크로드 처리 속도를 향상시킵니다.

!!!note 포트 입력 없음
VS Code(8443) · SSH(22) · JupyterLab(8888) 표준 포트가 자동으로 열립니다. 별도 포트 설정 UI는 없습니다.
!!!

!!!warning 리소스 한도 초과
소속 그룹의 리소스 한도를 초과하면 컨테이너를 생성할 수 없습니다. 상단 헤더에서 현재 그룹의 잔여 리소스를 확인하세요.
!!!

## 이미지 선택

Step 2의 이미지 영역에서 세 가지 방식 중 하나를 선택합니다.

| 방식 | 설명 |
|------|------|
| 직접 입력하기 | Docker Hub 등 퍼블릭 이미지 주소를 직접 입력 |
| 레지스트리에서 이미지 선택 | 관리자가 등록한 Private Registry에서 탐색하여 선택 |
| 커스텀 이미지 | 사용자가 직접 등록한 커스텀 이미지에서 선택 |

자세한 내용은 [이미지 관리](./image.md)를 참고합니다.

---

## 스토리지 마운트

기존에 생성한 스토리지를 컨테이너 내부 경로에 마운트합니다. 스토리지 목록에는 그룹 스토리지 사용 현황(사용 중 / 최대 / 사용 가능)이 함께 표시됩니다.

```
스토리지: my-dataset
마운트 경로: /workspace/data
```

스토리지가 없는 경우 **새 스토리지 생성** 버튼을 누르면 생성 모달이 열립니다.

| 항목 | 설명 |
|------|------|
| 이름 | 스토리지 이름 |
| 용량 | 슬라이더로 크기 설정 |
| 스토리지 유형 | 클러스터에 등록된 StorageClass (예: nfs-csi) |
| 접근성 | Group (그룹 내 공유, 현재 고정값) |

---

## SSH Key

프로필에 등록한 SSH Key를 선택하면, 컨테이너 생성 시 공개키가 자동으로 주입됩니다. SSH 접속 시 비밀번호 없이 Key 기반 인증을 사용할 수 있습니다.

등록된 Key가 없는 경우 **SSH Key 등록** 버튼을 클릭하면 [설정 페이지](/settings/index.md)의 등록 모달이 열립니다.

---

## 컨테이너 상세

목록에서 컨테이너 이름을 클릭하면 상세 페이지로 이동합니다.

### 컨테이너 정보

| 항목 | 설명 |
|------|------|
| 컨테이너 이름 | 식별 이름 |
| 상태 | 현재 실행 상태 |
| 컨테이너 ID | 내부 식별자 |
| 컨테이너 이미지 | 사용 중인 이미지 |
| 인스턴스 | CPU · 메모리 · 가속기 |
| 소유자 | 생성한 사용자 |
| 그룹 | 소속 그룹 |
| 마운트된 스토리지 | 마운트된 스토리지 목록 |
| 환경 변수 | 설정된 환경 변수 목록 |

### 접속 정보 카드

상세 페이지 상단에 표준 포트 3개의 접속 카드가 표시됩니다.

| 카드 | 동작 |
|------|------|
| **VS Code** | code-server를 브라우저로 열기. 미실행 시 Desktop VS Code + Remote-SSH 폴백 |
| **SSH** | 시스템 터미널 앱으로 SSH 연결 + 명령어 클립보드 복사 |
| **Jupyter** | JupyterLab을 브라우저로 열기 |

각 카드에는 **열기** 버튼과 **복사** 버튼이 있습니다. 외부 도구로 연결할 때는 복사된 주소를 사용하세요.

!!!note Base image 요구사항
표준 포트 접속이 동작하려면 컨테이너 이미지 안에서 code-server / SSH daemon / JupyterLab이 실행 가능해야 합니다. [Base image 가이드](https://github.com/bricksum/cluma/blob/main/docs/container-base-image-420.md)를 참고하세요.
!!!

!!!warning VS Code Desktop 폴백 요구
- VS Code Desktop 앱이 설치되어 있어야 합니다.
- [Remote - SSH](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-ssh) 확장이 설치되어 있어야 합니다.
!!!

### Pod 진단

상세 페이지의 **Pod 진단 조회** 버튼을 누르면 Kubernetes 단의 실제 상태를 확인할 수 있습니다.

| 항목 | 설명 |
|------|------|
| Phase | Pending / Running / Succeeded / Failed / Unknown |
| Node | Pod가 배치된 노드 이름 |
| Pod IP | 클러스터 내부 IP |
| Conditions | PodScheduled · Initialized · ContainersReady · Ready · ContainersStarted |
| Container Statuses | 컨테이너별 ready / restarts 카운트 |
| Events | Kubernetes 이벤트 목록 |

권한은 자기 컨테이너에만 적용됩니다 (관리자는 모두 조회 가능).

### 컨테이너 로그

상세 페이지에서 **로그 보기**를 클릭하면 컨테이너의 표준 출력을 실시간으로 확인할 수 있습니다.

### 포트 정보

상세 페이지에는 표준 포트(`vscode` / `ssh` / `jupyter`)의 외부 접속 주소(`노드IP:포트`)와 내부 포트가 read-only로 표시됩니다.

!!!note 표준 포트는 변경할 수 없습니다
v1.1부터 표준 포트가 자동 노출되며, 사용자가 추가/삭제할 수 없습니다. 사용자 정의 포트 API는 v1.2에서 제거 예정입니다.
!!!

## 컨테이너 삭제

컨테이너 목록의 삭제 아이콘 또는 상세 페이지 **컨테이너 삭제** 버튼을 클릭합니다.

삭제 확인 모달에서 컨테이너 이름을 직접 입력해야 삭제 버튼이 활성화됩니다.

!!!danger 삭제 시 주의
컨테이너를 삭제하면 컨테이너 내부 데이터는 모두 사라집니다. 중요한 데이터는 반드시 마운트된 스토리지에 저장하세요.
!!!

---

## 템플릿으로 저장

자주 사용하는 컨테이너 설정을 템플릿으로 저장해두면, 다음에 한 번에 동일한 환경을 생성할 수 있습니다.

컨테이너 상세 페이지에서 **템플릿으로 저장** 버튼을 누르면 저장 모달이 열립니다.

| 항목 | 설명 |
|------|------|
| 이름 | 템플릿 이름 |
| 설명 | 템플릿 설명 |

저장 시 현재 컨테이너의 이미지 · 인스턴스 · 환경 변수 · 포트 · Shared Memory · 마운트한 스토리지가 그대로 기록됩니다. 모달 하단에 저장될 설정의 미리보기가 표시됩니다.

!!!note 템플릿과 스토리지
마운트한 스토리지가 그대로 기록됩니다. 나중에 그 스토리지가 삭제되면 이 템플릿으로는 컨테이너를 만들 수 없습니다.
!!!
