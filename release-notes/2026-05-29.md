# 2026-05-29 — v1.1.0

NCC 시범운영(2026-06-01 시작)을 위한 정식 릴리스. 표준 포트 자동화, 보안 격리, GPU 자원 모델 전면 개편이 포함됩니다.

---

## 🆕 신규 기능

### 표준 포트 자동 노출

모든 신규 컨테이너에 세 가지 표준 포트가 backend에서 자동 노출됩니다.

| 포트 이름 | 컨테이너 내부 | 용도 |
|----------|-------------|------|
| `vscode` | 8443 | VS Code Web (code-server) |
| `ssh` | 22 | SSH 접속 |
| `jupyter` | 8888 | JupyterLab |

- 컨테이너 생성 모달의 **포트포워딩 입력 UI 완전 제거**.
- 컨테이너 상세 페이지에 **접속 정보 카드 3개** (열기 / 복사).
- VS Code 카드는 code-server 우선, 미실행 시 Desktop VS Code + Remote-SSH로 폴백.
- 시스템 표준 포트 이름(`vscode` / `ssh` / `jupyter`)은 보호되어 사용자 임의 추가/삭제 불가.

**Base image 책임**: 사용자 이미지가 위 세 서비스를 컨테이너 안에서 직접 실행해야 합니다. [Base image 가이드](https://github.com/bricksum/cluma/blob/main/docs/container-base-image-420.md) 참고.

### 사용자용 Pod 진단

컨테이너 상세 페이지에 **Pod 진단** 섹션 추가.

- Phase, Node, Pod IP
- Conditions (PodScheduled / Initialized / ContainersReady / Ready / ContainersStarted)
- Container Statuses (ready / restarts)
- Events (Kubernetes events 최근 목록)

권한: 자기 컨테이너만 (관리자는 모두). 백엔드 endpoint: `GET /api/containers/{id}/describe`.

### 인스턴스 카탈로그

CPU/메모리를 직접 입력하던 방식에서 **노드 가용 자원 기반 사전 정의 인스턴스 선택** 방식으로 전환.

- GPU 수 × 노드 비례 CPU / 메모리
- 예: `bs-gpu-worker` (16 CPU / 125 GB / 3 GPU) → 1 GPU 인스턴스 = CPU 5 / Memory 41 GB
- 노드 자원 정보 없으면 fallback (CPU 4 / Memory 16 GB per GPU)
- backend endpoint: `GET /api/instance-types?node=X`

### 템플릿 — 마운트만 저장 정책

자주 쓰는 컨테이너 설정을 그룹 내 공유 템플릿으로 저장하고, 컨테이너 생성 모달 상단의 **빠른 시작** 영역에서 한 번에 만들 수 있습니다.

- 이미지 · 인스턴스 · 환경 변수 · 마운트한 스토리지 · Shared Memory · 포트 설정이 저장됩니다.
- 마운트 정보는 **자동 스토리지 생성 없이** 기록만 — 템플릿 사용 시 스토리지가 살아있어야 컨테이너 생성 가능.
- 누락된 스토리지가 있으면 사용 불가 배지와 함께 컨테이너 생성이 거부됩니다 (`TEMPLATE_STORAGE_MISSING`).
- 템플릿 카드에서 호버 → 휴지통 아이콘으로 삭제. (편집 미지원 — 같은 설정으로 새로 만들어 저장)

### Shared Memory 설정

멀티 GPU 학습 시 필요한 `/dev/shm` 크기를 컨테이너 생성 시 지정 가능. 템플릿에도 함께 저장됩니다.

### GPU 비례 자원 자동 할당

인스턴스 preset의 CPU/메모리가 노드 가용 자원에 비례하여 자동 산정됩니다 (이전: 고정 4 core / 16 GB per GPU).

- `Math.floor` 라운딩 + 최소 1 (overcommit 방지)

### 표준 InstanceCard 컴포넌트

기존 `InstancePresetCard`를 `<InstanceCard variant="...">`로 표준화. selectable (생성) / summary (홈/목록) / detail (상세) 3가지 변형 지원으로 향후 다른 페이지에서 재사용 가능.

### 감사 로그 페이지

관리자 메뉴에 **감사 로그** 추가. 모든 주요 동작(인증 / 컨테이너 / 스토리지 / 사용자 / 그룹 / 템플릿 / 레포지토리)이 사용자 · 결과 · IP · 소요 시간과 함께 기록됩니다. 필터 · 페이지네이션 · 상세 모달 지원.

## 🛡 보안 / 격리

### Pod Security Admission `baseline`

그룹 namespace에 `pod-security.kubernetes.io/enforce: baseline` 라벨 자동 적용. 다음 옵션 Pod는 admission에서 거부됩니다.

- `hostNetwork` / `hostPort`
- `hostPID` / `hostIPC`
- `privileged: true`

### NetworkPolicy 자동 생성

그룹 namespace에 `cluma-group-isolation` NetworkPolicy 자동 생성.

- intra-namespace 허용
- `ingress-nginx` + `cluma-system` namespace 허용
- 외부 0.0.0.0/0 → 8443 / 22 / 8888 (표준 포트만) 허용
- 그 외 cross-namespace 트래픽 차단

## 🚫 사용자 영향 변경

- **컨테이너 생성 모달의 포트포워딩 입력 영역 사라짐** — 자동 노출로 대체.
- **컨테이너 상세 페이지의 포트 추가/삭제 버튼 사라짐** — read-only 목록.
- **GPU 노드에 CPU-only 인스턴스 생성 시도 시 거부** (한글 에러 메시지). AI 인프라 활용 극대화 원칙. 사용자는 GPU 할당 후 컨테이너 내부에서 CPU 작업 자유롭게 사용.
- **CPU/메모리 직접 입력 → 인스턴스 카탈로그 선택**으로 변경.
- **템플릿의 "원클릭 자동 생성 용량" 필드 제거** — 마운트만 기록 정책으로 통일.
- **사용자 정의 포트 추가/삭제 API는 deprecated** — v1.2에서 제거 예정.
