감사 로그

플랫폼 안의 주요 동작이 자동으로 남는 이력을 살펴봅니다.

관리자 메뉴 → 감사 로그 로 들어갑니다.

어떤 동작이 남나요

카테고리 예시
인증 (auth) 로그인 · 로그아웃 · 토큰 갱신
컨테이너 (container) 만들기 · 고치기 · 지우기 · 예약 · 상태 진단 조회
스토리지 (storage) 만들기 · 고치기 · 지우기 · 마운트
사용자 (user) 만들기 · 고치기 · 지우기 · 비밀번호 초기화
그룹 (group) 만들기 · 고치기 · 지우기 · 멤버 변경
템플릿 (template) 만들기 · 지우기
레포지토리 (repository) 등록 · 고치기 · 지우기

각 이벤트에는 사용자 · 동작 · 결과(성공/실패) · 결과 코드 · 처리 시간 · 어떤 자원에 영향이 갔는지 · IP · 요청 ID가 함께 남습니다.

필터

위쪽 필터 영역에서 보고 싶은 범위를 좁힙니다.

필터 어떤 식
시작일 / 종료일 분 단위까지 정할 수 있음
사용자 이메일로 거르기
카테고리 전체 / 인증 / 컨테이너 / 스토리지 / 사용자 / 그룹 / 템플릿 / 레포지토리
결과 전체 / 성공 / 실패
동작 동작 이름으로 검색 (예: container.create)

값을 바꾸고 적용을 누르면 결과가 다시 불러집니다. 초기화 로 처음 상태로 돌아갑니다.

표

열 어떤 값
시간 언제 일어났는지 (YYYY-MM-DD HH:MM:SS)
사용자 그 동작을 한 사람
동작 동작 이름 (예: container.create, auth.login)
카테고리 인증 / 컨테이너 / ...
결과 성공 / 실패
자원 영향을 받은 자원 (종류:이름)
결과 코드 HTTP 응답 코드
처리 시간 요청 처리에 걸린 시간 (ms / s)

줄을 누르면 상세 창이 열립니다.

상세 창

항목 어떤 정보
기본 시간 · 사용자 · 동작 · 카테고리 · 결과
요청 HTTP 방식 · 경로 · 결과 코드 · IP · 요청 ID
자원 영향을 받은 자원의 종류 · ID · 이름
세부 동작별 추가 정보 — 예: 컨테이너를 만들 때 쓴 인스턴스 · 이미지 등

요청 ID는 서버 로그와 1:1로 짝지어집니다. 실패 원인을 따라가다 서버 로그를 봐야 할 때, 같은 ID로 검색하면 됩니다.

페이지 넘기기

표 아래쪽에서 페이지를 넘깁니다. 기본은 50줄씩 보이고, 필터를 좁혀 두면 응답이 더 빨라집니다.

자주 쓰는 활용 예시

상황 어떻게
특정 사용자가 무엇을 했는지 사용자 필터 + 기간
실패한 컨테이너 생성 원인 카테고리=컨테이너, 결과=실패
이상한 로그인 시도 감지 카테고리=인증, 결과=실패
누가 그룹을 지웠는지 동작=group.delete
