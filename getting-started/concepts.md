# 핵심 개념

Cluma를 사용하기 전에 알아야 할 핵심 개념을 설명합니다.

---

## 유저 (User)

Cluma에 로그인하는 사용자 계정입니다. 모든 유저는 **관리자** 또는 **일반 사용자** 중 하나의 역할을 가집니다.

### 관리자 (Admin)

- 유저 생성 / 수정 / 삭제
- 그룹 생성 / 수정 / 삭제
- 유저를 그룹에 할당 또는 제거
- 전체 클러스터 리소스 모니터링
- 노드, 레포지토리 등 인프라 관리
- 감사 로그 조회

### 일반 사용자 (Regular User)

- 소속 그룹의 리소스 범위 내에서 컨테이너 생성 및 관리
- 스토리지 생성 및 마운트
- 개인 대시보드에서 리소스 현황 확인
- 그룹 소속 변경 불가 (관리자만 가능)

---

## 그룹 (Group)

유저를 묶고 리소스 한도를 정의하는 단위입니다.

- 유저는 하나 이상의 그룹에 소속될 수 있습니다.
- 그룹마다 CPU, 메모리, 디바이스(GPU 등), 스토리지 한도를 설정합니다.
- 그룹과 1:1로 대응하는 **Kubernetes Namespace**가 생성됩니다.
- 그룹 namespace에는 **Pod Security Admission `baseline`** + **NetworkPolicy**가 자동 적용되어, 그룹 간 격리가 보장됩니다.
- 유저는 소속 그룹의 리소스 한도 내에서만 컨테이너와 스토리지를 생성할 수 있습니다.
- 신규 유저는 `Default` 그룹에 자동으로 배정됩니다.

```
그룹 A (CPU: 32 cores / Memory: 128GB / GPU: 4개)
├── 유저 1
├── 유저 2
└── 유저 3
```

---

## 인스턴스 (Instance)

컨테이너를 생성할 때 선택하는 **사전 정의된 리소스 패키지**입니다. 클러스터에 등록된 노드의 가용 자원을 기준으로 자동 산정됩니다.

- GPU 수 × (노드 비례 CPU / 메모리)
- 예: `bs-gpu-worker` (16 CPU / 125 GB / 3 GPU) → 1 GPU 인스턴스 = CPU 5 / Memory 41 GB
- 노드 자원 정보가 없으면 fallback (CPU 4 / Memory 16 GB per GPU)
- 가속기 비탑재 노드는 CPU 전용 인스턴스만 제공

!!!note 인스턴스 카탈로그 자동 갱신
관리자가 노드를 추가하거나 그룹 한도를 변경하면, 사용 가능한 인스턴스 목록이 자동으로 다시 산정됩니다.
!!!

## 컨테이너 (Container)

Cluma에서 GPU 개발 환경의 핵심 단위입니다. Kubernetes Deployment 기반으로 동작하며 안정적인 워크로드 운영이 가능합니다.

### 컨테이너 구성 요소

| 항목 | 설명 |
|------|------|
| 이미지 | 컨테이너 실행에 사용할 Docker 이미지 |
| 인스턴스 | 사전 정의된 CPU / 메모리 / GPU 패키지 |
| 표준 포트 | VS Code(8443) · SSH(22) · JupyterLab(8888) — 자동 노출 |
| 스토리지 마운트 | PVC를 원하는 경로에 연결 |
| 환경 변수 | 컨테이너 실행 시 주입할 변수 |
| Shared Memory | `/dev/shm` 크기 (멀티 GPU 워크로드용) |
| SSH Key | 컨테이너 공개키 자동 주입 |

### 표준 포트 (자동 노출)

모든 신규 컨테이너에 세 가지 표준 포트가 자동으로 노출됩니다. 사용자가 별도로 설정할 필요가 없습니다.

| 포트 | 용도 |
|------|------|
| `vscode` (8443) | VS Code Web (code-server) |
| `ssh` (22) | SSH 접속 |
| `jupyter` (8888) | JupyterLab |

컨테이너 이미지(base image) 안에서 위 세 서비스가 실제로 실행되어야 합니다.

!!!warning Base image 요구사항
사용자가 가져오는 컨테이너 이미지에 code-server / SSH daemon / JupyterLab이 실행 가능한 형태로 포함되어 있어야 카드 버튼이 정상 동작합니다. 권장 이미지는 [이미지 가이드](/user-guide/image.md)를 참고하세요.
!!!

## 템플릿 (Template)

자주 사용하는 컨테이너 설정을 그룹 내에서 공유하는 단위입니다.

- 이미지 · 인스턴스 · 환경 변수 · 마운트한 스토리지 · Shared Memory 설정이 그대로 저장됩니다.
- 그룹 멤버 누구나 템플릿을 선택해 한 번에 동일한 환경을 생성할 수 있습니다.
- 템플릿에 기록된 스토리지가 삭제되면 해당 템플릿으로 컨테이너를 만들 수 없습니다 (오류 메시지로 안내).

---

## 스토리지 (Storage)

데이터를 영구적으로 저장하고 컨테이너에 마운트할 수 있는 저장 공간입니다. Kubernetes PVC(Persistent Volume Claim) 기반으로 동작합니다.

### StorageClass

관리자가 클러스터에 등록한 StorageClass(NFS, Local 등)를 선택하여 스토리지를 생성합니다.

### 접근성

- **Group**: 동일 그룹 내 멤버가 공유 (현재 기본값)

---

## 이미지 (Image)

컨테이너 실행에 사용할 Docker 이미지입니다.

- 관리자가 등록한 **레포지토리**에서 이미지를 탐색하고 선택할 수 있습니다.
- 퍼블릭 이미지 주소를 직접 입력할 수도 있습니다.
- 일반 사용자도 커스텀 이미지를 직접 등록하고 관리할 수 있습니다.

---

## 가속기 (Accelerator) / MIG

NVIDIA GPU 외에도 향후 NPU 등 다양한 가속기 유형을 지원하기 위해, Cluma는 디바이스를 **가속기 유형(Accelerator Type)** 단위로 추상화합니다.

- 그룹별로 가속기 유형별 한도를 설정합니다 (예: NVIDIA A100 × 4).
- 인스턴스 카드에는 가속기 모델명과 수량이 함께 표시됩니다 (예: `A100 × 2`).
- NVIDIA Multi-Instance GPU(MIG)를 사용하면 하나의 GPU를 여러 워크로드에 분할 할당할 수 있습니다.

---

## 보안 격리

Cluma는 그룹 namespace에 두 가지 보안 정책을 자동 적용합니다.

| 정책 | 효과 |
|------|------|
| Pod Security Admission `baseline` | `hostNetwork` / `hostPort` / `hostPID/IPC` / `privileged` 컨테이너 거부 |
| NetworkPolicy `cluma-group-isolation` | 그룹 간 네트워크 격리. 표준 포트만 외부 0.0.0.0/0에 노출. ingress-nginx · cluma-system namespace는 허용 |

Cluma 자체 흐름은 영향 없으며, 외부에서 임의로 Pod 매니페스트를 만들어 namespace에 배포할 때 차단됩니다.

## 감사 로그 (Audit Log)

관리자/사용자의 주요 동작이 자동으로 기록됩니다.

- 인증(로그인 · 로그아웃 · 토큰 갱신)
- 컨테이너 · 스토리지 · 사용자 · 그룹 · 템플릿 · 레포지토리 CRUD
- 성공 / 실패 결과 + HTTP 상태 코드 + 소요 시간

관리자만 [감사 로그](/admin-guide/audit-logs.md) 페이지에서 조회할 수 있습니다.
