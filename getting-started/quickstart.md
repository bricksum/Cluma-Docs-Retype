# 사용자 빠른 시작

처음 Cluma를 사용하는 경우 아래 순서로 진행합니다.

---

## 1단계 — 로그인

관리자로부터 받은 계정 정보로 로그인합니다.

로그인 후 헤더 상단의 **그룹 선택** 드롭다운에서 소속 그룹이 표시되는지 확인합니다. 그룹이 없는 경우 관리자에게 그룹 배정을 요청합니다.

---

## 2단계 — 잔여 리소스 확인

상단 헤더에서 현재 그룹의 CPU / 메모리 / GPU / 스토리지 잔여량을 확인합니다.

컨테이너와 스토리지는 그룹의 리소스 한도 안에서만 생성할 수 있습니다. 잔여 리소스가 부족한 경우 관리자에게 한도 증가를 요청합니다.

---

## 3단계 — 스토리지 생성 (선택)

학습 데이터, 모델 파일 등 컨테이너가 삭제되어도 유지해야 할 데이터는 스토리지에 저장합니다.

1. 사이드바 → **스토리지** → **스토리지 생성**
2. 이름, 용량(GB), 스토리지 유형을 입력하고 생성합니다.

자세한 내용은 [스토리지 관리](/user-guide/storage.md)를 참고합니다.

!!!note 스토리지 없이 시작해도 됩니다
컨테이너 생성 단계에서 **새 스토리지 생성** 버튼을 눌러도 됩니다. 처음에는 그냥 컨테이너부터 만들어보세요.
!!!

---

## 4단계 — SSH Key 등록 (선택)

비밀번호 없이 SSH로 컨테이너에 접속하려면 SSH Key를 미리 등록합니다.

1. 우상단 사용자 메뉴 → **설정** → **SSH Key 추가**
2. Key 이름을 입력하고 공개키를 직접 입력하거나 `.pub` 파일을 업로드합니다.

---

## 5단계 — 컨테이너 생성

1. 사이드바 → **컨테이너** → **새 컨테이너 만들기**
2. 노드를 선택하면 **컨테이너 시작** 모달이 열립니다. 두 가지 진입점이 있습니다.

### 5-A. 템플릿으로 시작 (빠른 경로)

저장된 템플릿이 있으면 모달 상단에 카드 목록으로 표시됩니다.

1. 원하는 템플릿 카드를 클릭합니다.
2. 확인 모달에서 컨테이너 이름을 입력합니다.
3. **생성**을 클릭하면 즉시 만들어집니다.

이미지 · 인스턴스 · 환경 변수 · 스토리지 마운트 · Shared Memory 가 템플릿 그대로 적용됩니다.

### 5-B. 새로 시작 (인스턴스 직접 선택)

템플릿이 없거나 다른 설정이 필요하면 **또는 새로 시작** 영역에서 인스턴스를 직접 선택합니다.

| Step | 항목 |
|---|---|
| Step 1 | 인스턴스(CPU/메모리/GPU 패키지) 선택 → **다음** |
| Step 2 | 컨테이너 이름, 이미지, 환경 변수, 스토리지 마운트, Shared Memory, NUMA-aware CPU(선택) 설정 → **생성** |

선택한 인스턴스의 자원은 **다음** 클릭 시점부터 5분간 임시 예약됩니다. 그 시간 안에 생성을 마쳐야 합니다.

!!!note 포트는 자동
VS Code(8443) · SSH(22) · JupyterLab(8888) 표준 포트가 자동으로 열립니다. 별도 설정이 필요하지 않습니다.
!!!

!!!warning GPU 노드에 CPU-only 인스턴스는 거부됩니다
가속기가 탑재된 노드에는 GPU를 1개 이상 할당해야 합니다. CPU만 필요한 워크로드는 CPU 전용 노드를 사용하세요.
!!!

---

## 6단계 — 컨테이너 접속

컨테이너 상태가 **Running**이 되면 상세 페이지에서 접속할 수 있습니다.

상세 페이지 상단의 **접속 정보 카드 3개**를 통해 즉시 연결됩니다.

| 카드 | 동작 |
|------|------|
| **VS Code** | 브라우저에서 code-server 열기 (없으면 Desktop VS Code + Remote-SSH 폴백) |
| **SSH** | 시스템 터미널 앱으로 SSH 연결 + 명령어 클립보드 복사 |
| **Jupyter** | 브라우저에서 JupyterLab 열기 |

각 카드에는 **열기**와 **복사** 버튼이 있어, 외부 도구로 직접 연결할 때는 복사된 주소를 사용하면 됩니다.
