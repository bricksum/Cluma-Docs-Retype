# 트러블슈팅

Cluma 사용 중 자주 발생하는 문제와 해결 방법을 설명합니다.

---

## 컨테이너

### 컨테이너가 Pending 상태에서 전환되지 않는 경우

**클러스터 GPU 리소스 부족**

클러스터에 사용 가능한 GPU가 없는 경우입니다. 관리자 대시보드에서 GPU 사용 현황을 확인합니다. 다른 컨테이너가 종료되면 자동으로 스케줄링됩니다.

**그룹 리소스 한도 초과**

소속 그룹의 GPU 할당량을 초과한 경우입니다. 헤더 상단에서 그룹 잔여 리소스를 확인하고 불필요한 컨테이너를 삭제합니다.

**노드 비활성 상태 (Drained)**

관리자에게 노드 활성화 상태 확인을 요청합니다.

**Pod 진단 활용**

컨테이너 상세 페이지의 **Pod 진단 조회** 버튼으로 Phase / Conditions / Events 를 확인하면 원인을 정확하게 파악할 수 있습니다.

---

### GPU 노드에 CPU-only 인스턴스 생성이 거부되는 경우

v1.1부터 가속기가 탑재된 노드에는 GPU를 1개 이상 할당해야 합니다.

```
오류: CONTAINER_CPU_ONLY_ON_GPU_NODE
GPU 노드에 CPU-only 인스턴스는 생성할 수 없습니다.
GPU 1개 이상이 할당된 인스턴스를 선택하세요.
```

CPU만 필요한 워크로드는 CPU 전용 노드를 사용하거나, 컨테이너 내부에서 GPU 없이 CPU 작업만 실행하세요.

---

### `hostPort` / `hostNetwork` / `privileged` 컨테이너가 거부되는 경우

그룹 namespace에는 **Pod Security Admission `baseline`** 이 자동 적용됩니다. 다음 옵션을 사용하는 Pod 매니페스트는 admission 단계에서 거부됩니다.

- `hostNetwork`
- `hostPort`
- `hostPID` / `hostIPC`
- `privileged: true`

Cluma 자체 흐름은 영향이 없으며, 외부에서 임의로 매니페스트를 만들어 namespace에 배포할 때만 차단됩니다. 보안 정책으로 의도된 동작입니다.

---

### 컨테이너가 예기치 않게 중지된 경우

**OOM (메모리 초과)**

컨테이너에 할당된 메모리를 초과하면 강제 종료됩니다. 컨테이너 로그를 확인하고 더 큰 메모리를 가진 인스턴스로 재생성합니다.

**Pod 진단 활용**

Pod 진단의 Events 섹션에서 OOMKilled / Evicted 등의 이벤트가 표시됩니다.

---

### VS Code / SSH / Jupyter 카드 버튼이 동작하지 않는 경우

표준 포트는 자동으로 열리지만, **컨테이너 안에서 실제로 서비스가 실행되어야** 동작합니다.

- VS Code: code-server (포트 8443)
- SSH: sshd (포트 22)
- JupyterLab: jupyter (포트 8888)

base image 안에서 위 세 서비스가 실행되도록 구성되어 있는지 확인합니다. 빈 base image를 사용한 경우, 컨테이너 내부에서 직접 설치하거나 [base image 가이드](https://github.com/bricksum/cluma/blob/main/docs/container-base-image-420.md) 를 참고하세요.

순서대로 확인:

1. 컨테이너 상태가 `Running`인지 확인
2. Pod 진단의 Container Statuses에서 ready 상태 확인
3. 컨테이너 안에서 `ss -ltnp` 또는 `netstat -ltnp`로 포트가 열려 있는지 확인
4. 카드의 **복사** 버튼으로 URL을 받아 직접 접속 시도

---

### 템플릿으로 컨테이너 생성이 실패하는 경우

템플릿에 기록된 스토리지 중 하나라도 삭제된 경우입니다.

```
오류: TEMPLATE_STORAGE_MISSING
템플릿에 기록된 스토리지가 존재하지 않습니다: my-old-dataset
```

해결 방법:

- 누락된 스토리지를 재생성하고 동일한 이름으로 설정합니다.
- 또는 같은 설정으로 새 컨테이너를 만든 뒤, 현재 스토리지로 다시 템플릿을 저장합니다.

---

## 스토리지

### 스토리지 마운트가 되지 않는 경우

- 스토리지가 정상적으로 생성된 상태(`active`)인지 확인
- 마운트 경로가 올바르게 입력되었는지 확인
- 그룹의 스토리지 용량 한도를 초과하지 않았는지 확인

### 스토리지 용량이 부족한 경우

기존 스토리지의 용량 확장은 StorageClass와 PVC가 expand-allowed로 설정되어 있어야 가능합니다. 그룹의 스토리지 총 한도 내에서만 확장할 수 있습니다. 한도 초과가 필요한 경우 관리자에게 요청합니다.

---

## 이미지

### 이미지를 불러올 수 없는 경우

- 레지스트리가 관리자에 의해 정상 등록되어 있는지 확인
- 이미지 이름과 태그가 정확한지 확인
- 퍼블릭 이미지 주소를 직접 입력한 경우 클러스터에서 외부 네트워크 접근이 가능한지 확인

## 클러스터 모니터링

### 모니터링 탭에서 Grafana가 열리지 않는 경우

frontend 빌드의 `NEXT_PUBLIC_GRAFANA_URL` 환경변수가 설정되지 않은 상태입니다.

- 배포 담당자에게 환경변수 설정을 요청하거나
- 기본 주소 `http://grafana.internal`을 사용하려면 클라이언트 PC의 `/etc/hosts`에 노드 IP 매핑을 추가합니다.

---

## 문제가 해결되지 않는 경우

관리자에게 아래 정보를 함께 전달합니다.

- 발생한 증상 및 시간
- 컨테이너 이름 및 상태
- 컨테이너 로그 (상세 페이지 → 로그 보기)
- Pod 진단 결과 (상세 페이지 → Pod 진단 조회)
- 감사 로그의 Request ID (관리자만 조회 가능)
